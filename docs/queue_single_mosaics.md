# Proposed Single Pointing against Queue mosaics

The application entry point accepts `queue_single_mosaics=True` for a validated
fixed Single Pointing request selecting Queue. It loads the snapshot once and
evaluates every Custom group and Rectangle row. This backend increment returns
a separate structured report for later browser integration.

The original proposed geometry and coordinates are retained. The position
adapter supplies one probe to the existing spherical beam-union kernel.
An inside relation to any bound candidate pointing satisfies POS-SINGLE.
A negative result requires every possible pointing relation to be outside.
Incomplete geometry retains UNKNOWN as needed.
Spherical separation <= candidate radius is inclusive, matching the current
Queue Single Pointing convention without an equality band. Each array uses its own candidate frequency and diameter.

Custom uses the existing grouped CSV centres and array interpretation.
Rectangle uses the existing generated array grids. Scientific comparisons
reuse the Queue angular, continuum and LINE numerical evaluators. Array OR
combines complete branches belonging to the same candidate only. Requested
RMS is compared directly with the existing formulas and without overlap gain.

SPS rows remain present with SPECTRAL_SCAN_NOT_EXPANDED. Search completeness
remains NOT_ESTABLISHED. The inventory also records TP, Galactic and candidate
types outside this increment. Single Field evaluation continues through its
existing workflow until unified orchestration is integrated.

The scientific interpretation follows the Single Field position clause in
[ALMA Users' Policies, Appendix A](https://almascience.eso.org/documents-and-tools/cycle13/alma-user-policies).
All geometric conclusions retain the provisional CSV model provenance.
