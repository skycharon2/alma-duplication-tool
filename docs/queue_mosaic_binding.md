# Custom CSV → OT-checked coverage bindings

The third backend increment reads the CSV directly, reconstructs the selected
Custom candidate and compares its diagnostic centres with a supplied OT Absolute
pointing export. It produces an audit plus `coverages`, consumable directly by
[the per-array position CLI](queue_mosaic_position.md). No handwritten pointing
JSON is required. The shared evaluator/browser remains unchanged.

See the [seven-point controlled OT experiment](../examples/queue-mosaic-ot/README.md)
for ready-to-import offset inputs. Its [native OT exports](../tests/fixtures/ot_pointings/custom_offsets_2026_11_02/README.md)
now validate the seven-point coordinate case (2026-11-02). The 12-m list matches;
the 7-m list contains three independent generated points. Geometry parity does
not establish spectral setup equivalence or operational Queue ownership.

## Inputs and evidence

```sh
python -m alma_duplicate.cli.queue_mosaic_binding \
  --queue-csv /path/to/queue.csv \
  --ot-pointings /path/to/absolute-pointings.txt \
  --binding /path/to/binding.json \
  --output /path/to/new-binding-audit.json
```

The binding JSON contains `candidate_id`, `snapshot_sha256`, `ot_sha256`,
`diameter_m`, `evidence_ref`, `confirm_fixed_icrs`, `association_confirmed` and
`complete`. See the engineering template for its exact shape. The reference must
identify supporting target/setup/array evidence; hashes must match the CSV and OT
bytes. Coordinate agreement alone does not establish those associations.
Assertions remain caller-supplied, not independently authenticated.

The module reconstructs from parsed CSV instead of trusting edited diagnostic
centres. It reuses existing Queue array inference and `candidate_frequency`:
positive Ref.Frequency, or the existing normalized sky-SPW bandwidth-weighted
fallback when Ref.Frequency is zero. Frequency source and notes are recorded;
frequency disagreements or unavailable frequency prevent coverage generation.

## Parity and unresolved results

Comparison uses great-circle distances and a one-to-one bipartite matching within
an explicit tolerance (default 0.001 arcsec, maximum 1 arcsec). OT row order can
differ. Duplicate coordinates retain multiplicity; one OT row cannot validate
several CSV rows. Matching uses augmenting paths rather than greedy nearest-point
assignment. Equal counts and a full matching are required. A selected matching is
coordinate correspondence, not proof of unique physical pointing identity.

The audit retains source rows, raw columns and units, reference evidence, OT text
and hash, selected pairs/errors, unmatched row IDs, offset method and tolerance.
One million comparison pairs is the limit. Invalid identities, inputs or budget
raise errors. Missing confirmations, unsupported centres or failed parity produce
`UNRESOLVED` and an empty coverage list. CLI exit 0 means an audit was written,
including unresolved audits; exit 2 means input/output failure. Files are never
overwritten.

A successful binding applies only to the selected inferred array. `complete`
is retained separately; full coordinate matching does not prove full candidate
coverage. Other arrays remain unknown. Rectangle and non-equatorial unresolved
CSV centres are not converted by this module. OT/CSV parity does not globally
approve the spherical offset convention for other targets or frames.

Pass the audit as `--coverage` to `cli.queue_mosaic_position`; its full evidence is
embedded in the resulting position report. Audit candidate and snapshot identity
must agree with the selected reconstruction. Existing explicit coverage-array
inputs remain supported. Complete duplication criteria are still not evaluated.

## Validation scope

Automated tests cover reordered exports, repeated coordinates, missing/extra
points, negative offsets, RA wrap, high declination, unconfirmed ownership,
source/hash mismatches, frequency fallback, budget limits, CLI output protection,
and CSV → binding → position integration. The coordinate exports generated by
these tests are engineering oracles, not OT acceptance measurements.
